# Прототип мониторинга расхождений заказов с 1С

Раз в час сверяет заказы с выгрузкой 1С, запоминает найденные расхождения
и показывает только новые, изменившиеся и исправленные. Переиспользует
движок сверки из задания `01-orders-1c-sync` и его данные (31 заказ,
40 строк номенклатуры). Внешних зависимостей нет, PHP 8.1+.

Быстрая проверка из корня репозитория:

```cmd
run.cmd -Task 06
```

## Файлы

```
prototype/
├── monitor-discrepancies.php     # CLI: сверка + диф + алерты
├── fixtures/
│   ├── state-baseline.json       # снимок первого запуска (14 расхождений)
│   └── orders-next.json          # следующий срез: 2 исправлено, 1 новое
├── output/
│   └── example-alert.txt         # пример вывода прототипа
└── README.md
```

## Запуск

```powershell
cd 06-open-improvement

# 1. Базовая линия: сохранить текущие расхождения, без алертов
#    (снимок по умолчанию: ..\var\monitor-state.json)
php prototype\monitor-discrepancies.php --baseline

# 2. Следующий запуск по новому срезу заказов
#    (состояние берётся из ..\var\monitor-state.json, созданного выше)
php prototype\monitor-discrepancies.php --orders=prototype\fixtures\orders-next.json

# 3. То же в JSON — payload для вебхука
php prototype\monitor-discrepancies.php --orders=prototype\fixtures\orders-next.json --json
```

Для демонстрации без первого шага можно взять готовый снимок из фикстур:

```powershell
php prototype\monitor-discrepancies.php `
  --state=prototype\fixtures\state-baseline.json `
  --orders=prototype\fixtures\orders-next.json
```

Если PHP не установлен в системе, вместо `php` используйте `..\.tools\php\php.exe`
(портативная сборка, каталог исключён из git).

Ожидаемый результат второго запуска: «Новых: 1 | изменилось: 0 | исправлено: 2»,
в алертах — `MP-24002 / TS-1007` (2,90 против 2,40), в исправленных —
`MP-24003 / TS-1004` и `MP-24030 / TS-1003`. Код возврата `2`.

## Параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--orders=PATH` | данные задания 01 | заказы: JSON-файл или URL API |
| `--nomenclature=PATH` | данные задания 01 | CSV-выгрузка номенклатуры 1С |
| `--state=FILE` | `..\var\monitor-state.json` | снимок прошлого запуска |
| `--save=FILE` | состояние при `--baseline` | куда записать новый снимок |
| `--baseline` | — | первый запуск: только сохранить снимок |
| `--log=FILE` | `..\var\monitor.log` | лог сверки; если недоступен — `NUL` |
| `--json` | — | вывод в JSON вместо текста |

Коды возврата: `0` — новых расхождений нет, `2` — есть новые или изменившиеся,
`1` — ошибка входных данных.

## Как считается диф

Ключ расхождения — `заказ|артикул|код` (например
`MP-24002|TS-1007|PRICE_MISMATCH`). Цифры и текст в ключ не входят, поэтому
изменение цены с 2,40 на 2,90 остаётся тем же расхождением и помечается
«изменилось», а не «новое».

Снимок хранит `first_seen`, поэтому по нему видно, сколько расхождение
висит и когда исправлено. Отменённые заказы, дубли выгрузки и нормализация
артикула в алерты не попадают — это шум для мониторинга цен и остатков.

## Что поменять на стенде

1. `--orders` — на реальный API маркетплейса (поддерживается URL).
2. `--state`/`--save` — на таблицу в БД, чтобы история не терялась.
3. Вместо вывода — webhook в чат; `--json` даёт готовый payload.
4. Перед запуском проверять свежесть выгрузки 1С: файл старше 24 часов —
   отдельный алерт, иначе можно месяц сверять устаревшие данные.
5. Cron раз в час; первый запуск после внедрения — `--baseline`.
