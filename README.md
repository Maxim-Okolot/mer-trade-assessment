# mer-trade-assessment

Тестовые задания: разбор инцидентов поддержки, сверка заказов с 1С и идея
улучшения с прототипом. Каждую работу можно проверить одной командой.

## Отчёт кандидата

### Выбранные задания

- **Обязательное:** 04 — разбор обращений поддержки по логам.
- **На выбор:** 01 — сопоставление заказов маркетплейса с выгрузкой 1С.
  Почему именно оно: это самый близкий к дистрибьютору сценарий (цены,
  остатки, обмен с 1С), и на его данных получился осмысленный прототип
  для задания 06.
- **06:** да — мониторинг расхождений заказов с 1С и рабочий прототип.

### Время

| Задание / часть | Время, мин | Комментарий |
|---|---:|---|
| 04 | 60 | Четыре обращения: причина, доказательства, действия, профилактика, ответ сотруднику; `04-incidents.md` |
| 01 | 150 | CLI-сверка, отчёт CSV/текст, лог, исправление трёх багов, README |
| 06 | 60 | Записка, прототип с дифом, фикстуры, проверка запуска |
| **Итого** | **270** | Около 4,5 часов чистой работы, без учёта настройки окружения |

### ИИ-инструменты

- **Что использовал:** ассистент DeepSeek Harness (модель deepseek-flash)
  с доступом к файлам и терминалу; PowerShell 5.1, портативный PHP 8.4,
  Git.
- **Для чего:** разбор логов (04), генерация и рефакторинг кода (01, 06),
  подготовка фикстур, тестовые прогоны, документация и README, проверка
  отчётов, подготовка запуска для проверяющего.
- **Примеры запросов, которые сработали:**
  1. «Разбери четыре обращения по логам: причина, доказательства, что
     сделать сейчас, профилактика и ответ сотруднику; в конце — порядок
     обработки, если всё пришло одновременно» — дал готовую структуру
     `04-incidents.md`.
  2. «Сделай прототип мониторинга расхождений на данных задания 01:
     снимок состояния и алерты только на новые расхождения» — дал рабочую
     логику дифа и фикстуры.
- **Где ИИ ошибся и как это заметили:**
  - сначала предложил «сторож очереди», но в данных задания 01 нет очереди
    и попыток — заметил при попытке переиспользовать выгрузки; переделали
    на мониторинг расхождений.
  - команда `icacls output /grant "$env:USERNAME:(OI)(CI)F"` падала:
    PowerShell съедал двоеточие; исправлено на `${env:USERNAME}`.
  - прототип писал лог в `prototype\` и падал с `Permission denied`;
    заметил на запуске, перенёс лог и состояние в `var\` и добавил
    запасные пути.
  - сгенерированный `run.ps1` без BOM не парсился PowerShell 5.1 —
    поймал на первом запуске, добавил BOM и обёртку `run.cmd`.
- **Что проверял вручную:**
  - пересчитал итоги по CSV: 16 / 9 / 4 / 2 и 14 расхождений по 13 заказам;
  - сверил цены и остатки с выгрузкой 1С (`TS-1004`, `TS-1012`, `TS-1025`);
  - проверил коды возврата 0 / 1 / 2 и что диф даёт ровно «1 новое, 2 исправлено»;
  - прогнал `run.cmd` на чистом снимке репозитория (`git archive`), без
    рабочей папки и лишних файлов;
  - проверил кодировки: BOM в CSV для Excel, UTF-8 в логах, кириллицу в консоли.

### Если бы это шло в прод

- **P0 — идемпотентность и очередь.** Сейчас сверка разовая; в проде нужен
  воркер с повторами, dedupe по `id` заказа и защитой от повторной передачи
  в 1С.
- **P0 — тесты и CI.** Unit-тесты на разбор CSV (BOM, запятые, пробелы),
  golden-тесты отчёта и дифа, прогон на фикстурах в CI.
- **P1 — мониторинг и алерты.** Watchdog на лаг очереди и `attempts`,
  dead-letter для «отравленных» заданий, алерты в чат, метрика времени
  до обнаружения.
- **P1 — логи.** Структурированные JSON-логи с correlation id, ротация,
  без секретов и персональных данных.
- **P1 — права доступа и секреты.** Read-only пользователь БД, секреты
  в vault, а не в query string и не в репозитории.
- **P2 — откат и фичефлаги.** Возможность отключить автопередачу, откатить
  миграции, хранить версии правил сверки.
- **P2 — производительность.** Индексы под выборку очереди, кэш каталога,
  пагинация API маркетплейса.

## Быстрый старт

Нужны Windows и PowerShell 5.1+. PHP 8.1+ желателен, но не обязателен:
скрипт проверки сам скачает портативную сборку, если PHP не найден.

Из корня репозитория:

```cmd
run.cmd
```

или, если PowerShell разрешает локальные скрипты:

```powershell
.\run.ps1
```

Отдельные работы:

```cmd
run.cmd -Task 01
run.cmd -Task 06
```

Если PHP нет, `run.cmd` сам скачает портативную сборку в `.tools\php`
(каталог исключён из git). Запретить скачивание: `run.cmd -NoBootstrap` —
тогда PHP 8.1+ нужно установить вручную и добавить в PATH.

## Что должно получиться

**Задание 01 — сверка заказов с номенклатурой 1С.** В консоли отчёт
по 31 заказу: 16 готовы, 9 требуют проверки, 4 заблокированы, 2 пропущены.
Код возврата `1` — это норма: есть заблокированные заказы.

**Задание 06 — мониторинг расхождений.** Первый запуск строит базовую линию
(14 расхождений по 13 заказам), второй — показывает диф по новому срезу:
новых 1, исправлено 2. Код возврата `2` — это норма: есть новые расхождения.

Все отчёты, снимки и логи пишутся в `var\` (каталог исключён из git):

| Файл | Что это |
|---|---|
| `var\01-report.csv` | отчёт по заказам для Excel |
| `var\01-report.txt` | тот же отчёт текстом |
| `var\01-app.log` | лог сверки |
| `var\monitor-state.json` | снимок расхождений после базовой линии |
| `var\monitor.log` | лог мониторинга |

Примеры отчётов также лежат в репозитории: `01-orders-1c-sync/output/`
и `06-open-improvement/prototype/output/`.

## Работы

| Папка | Что внутри |
|---|---|
| `01-orders-1c-sync/` | PHP-скрипт сверки заказов с 1С, исправленные баги `OrderTotal.php`, README с решениями |
| `04-support-incidents/` | разбор четырёх обращений по логам, `04-incidents.md` |
| `06-open-improvement/` | записка с идеей мониторинга расхождений и прототип на PHP |

Подробности запуска — в README каждой папки.

## Запуск без обёртки

```powershell
# сверка заказов
php 01-orders-1c-sync\bin\check-orders.php

# мониторинг: базовая линия, затем диф
php 06-open-improvement\prototype\monitor-discrepancies.php --baseline
php 06-open-improvement\prototype\monitor-discrepancies.php --orders=06-open-improvement\prototype\fixtures\orders-next.json

# самопроверка исправленных багов
php 01-orders-1c-sync\bugs\OrderTotal.php
```

Если PHP нет в PATH, используйте `..\.tools\php\php.exe` или путь,
который вывел `run.cmd`.
